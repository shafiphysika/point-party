# Classroom update - 10 October 2026

Original now shows a six-sided 3D die. Dice buddy, Full-screen and Surprise me migrate to a single Dice show with an animated original character. Dice machine adds a shaking chamber and lever. Magic wand remains available. Each roll style has a distinct synthesized sound, and the sound toggle controls all of them. Random selection, absent-student exclusion and everyone-gets-a-turn behavior remain in place.

Learning adventures adds the five supplied animated friends, pause controls, a session-only adaptive addition quest with hints and stars, and a teacher helper. The helper builds an age-specific lesson prompt for the linked free teacher AI tools. On-device FLAN-T5-small was tested in Chrome and produced poor drafts, so that experimental generator is not exposed in the released interface. Review any external AI answer before classroom use.

Resource ideas were informed by [AdaptedMind](https://www.adaptedmind.com/), [Jigzi](https://www.jewishinteractive.org/jigzi-home/) and [Seesaw](https://app.seesaw.me/). Their resources open through links; this update does not copy their content or import their student records. [Transformers.js documentation](https://huggingface.co/docs/transformers.js/v3.8.1/pipelines), [FLAN-T5-small](https://huggingface.co/Xenova/flan-t5-small), [Google free tier](https://ai.google.dev/gemini-api/docs/pricing), and [MagicSchool plans](https://www.magicschool.ai/pricing) describe the helper and linked AI options.

Email auth events now defer server requests until the callback returns and deduplicate session entry. Missing optional family setup no longer prevents teacher login. Errors distinguish expired links/codes, email delivery, rate limits and missing database setup.

The administrator permission panel controls points, activities and grades, materials, roster and attendance, and invitations separately for each teacher and school. The permission migration enforces these capabilities in PostgreSQL and storage, including direct RPC calls. New membership permissions default to points only; existing approval states are preserved. Class creation/deletion and backup restoration require all classroom editing permissions. Admins keep their existing server-verified privileges.

## Deployment order

1. Inspect the live Supabase schema. Do not rerun schema.sql on an existing installation. Confirm platform.sql and materials.sql were applied; if a prerequisite is missing, apply that specific migration first.
2. Run the reviewed supabase/permissions.sql in the project SQL Editor. It is transactional and safe to rerun. It does not approve or add users. If an UNSUPPORTED_*_DEFINITION error appears, the transaction aborts; review the existing function definition before adapting it.
3. Check Authentication > Emails > SMTP. If the default service is in use, configure an existing email provider. Supabase's default service only delivers to project-team addresses and is unsuitable for co-teacher onboarding; this restriction is described in [Supabase SMTP documentation](https://supabase.com/docs/guides/auth/auth-smtp). This project's custom SMTP is currently disabled.
4. Publish the saved source commits to the existing GitHub Pages repository and await its deployment. Preserve the site URL and audience.
5. Verify owner email sign-in, sign-out/reload, and co-teacher email delivery in separate sessions. Invite a teacher, approve the school membership, and use the panel to grant only the chosen capabilities. Verify denied writes, revocation and school isolation.
6. In Chrome, check all four dice modes, mute, reduced motion, small screens, all five friends, Number Quest and an actual on-device AI generation. SQL and DOM tests are not substitutes for these live checks.
